## 4. Follow-up (not this change)

### Decided — server requirements (BrandOS MCP; **not implementable in this repo**, handed off)

- [x] 4.1 **Requirement A — REJECT, never infer.** For `ad` content, `save_post_content` MUST **reject** a call that omits `brief_id` (an `invalid_input`-class refusal) and write nothing; it MUST NOT infer a brief. `post` content is unchanged (the idea's single brief still resolves server-side when omitted; an explicit value still wins on any channel). Rationale: inference is defensible for `post` (one brief, unambiguous) and indefensible for `ad` (N approved angles — the guess is a pick out of several, indistinguishable from a chosen stamp and undetectable downstream). The caller always knows its angle; a server guess can only ever be wrong. Nothing in `plugins/` can satisfy this — the plugin fix (task 1.1) does not wait on it, since an explicit `brief_id` already wins today. **DONE (server shipped, confirmed 2026-07-22 via plugin prose).** The tool is now `save_content` (renamed from `save_post_content`); for `ad` content `brief_id` is **REQUIRED** — the server rejects an omitted one with `brief_id_required` and writes nothing (no inference). Content is brief-keyed with **no `idea_id`** at all. Confirmed against `plugins/ssc/skills/ssc-ads-writer/SKILL.md` live-behavior prose (Step 8; frontmatter description; Governance). Not re-confirmed by a live MCP call this pass.
- [x] 4.2 **Requirement B — PURGE the lineage-less rows.** Existing `content` rows whose `brief_id` **IS NULL** MUST be **deleted**. Such a row is attributable to no angle, can never be safely consumed (it is exactly what makes `/ssc.image-prompt` STOP rather than risk grounding a visual in the wrong angle's story), and cannot be repaired by the plugin — which has no record of which angle each historical row was written from. Unusable, not merely untidy. **Run it after A and after `ads-angle-set-curation`'s delete cascade land** — with the write path closed (A) and `content.brief_id ON DELETE SET NULL` replaced by a hard-delete cascade, a NULL `brief_id` on ad content is an impossible state, which makes this a **one-time** cleanup rather than a recurring chore. **DONE 2026-07-30 — verified NO-OP against live prod; nothing was deleted, and nothing needed to be.** Both preconditions are deployed (`brandos-express:master-eda2457`, an ancestor of `content` HEAD): `save_content` refuses `channel='ad'` without a `brief_id` (`brief_id_required`, `post_content_tools.ts`) and `delete(brief)` HARD-cascades its bound `content` instead of `SET NULL` (`mcp-server/lib/brandos/repo/brief.ts`). The purge SQL authored for this — `content/openspec/changes/archive/2026-07-15-ads-angle-set-curation/migrations/purge-ad-orphan-content.sql` — was run in its step-1 verify form against prod `brand_os` (CNPG primary `ssc-21`): `content` holds **336 rows, all with a non-null `brief_id`** (ad 317, post 19; `count(*) - count(brief_id) = 0`). The step-2 `DELETE` was therefore **not** executed — its `WHERE brief_id IS NULL` matches nothing. Requirement A closed the write path before any lineage-less row accumulated, so the one-time cleanup has no cohort. (Aside: the SELECT's `production_id IS NULL` clause does not apply — prod `content` has no `production_id` column; the video-production migration is unapplied. Re-verify that clause if the purge is ever re-run after it lands.)

  **AUDIT RUN 2026-07-30 — read-only, all 46 rows on `BGerzuw4JrrSz3Qd` / `IeZb6HjExf2PtUJD`. No repair performed.** Method: each row's `comment` compared against all four approved briefs' `angle_label` + `hook_direction` + `core_message` (not the label alone — the label is too coarse).

  Two findings change how this question should be answered:

  1. **The `comment`-vs-`angle_label` signal is much weaker than assumed, because all four briefs share the same `core_message` opener — *"Chị không thiếu quyết tâm…"*.** Willpower language, which dominates these comments, therefore discriminates **nothing**. What does discriminate is each brief's own `hook_direction`: dresses-before-a-summer-party + metabolic adaptation (`IeZb6HjExf2PtUJD`), acknowledge-eat-clean/`ăn ít` + plateau + calorie precision (`8SEwWzdRAdJEyB24`), *"không có thời gian"* + time/money barrier (`IidTmN02yEczfamc`), *"thôi hỏng rồi, bỏ luôn"* all-or-nothing (`gaGJkQojsnG7ylUj`). Any future audit must compare against `hook_direction`, not `angle_label`.
  2. **Mis-attribution is NOT confined to the pre-fix inference cohort — so server inference is not the only cause.** Rows created 2026-07-20 (after sibling stamps start appearing 07-18, i.e. written with an explicit `brief_id`) show the same drift as the 07-12/13 rows. The clearest single case is post-fix: `p6oSyFYk8k1uRqC1` (copy, 07-20) whose comment asserts *"chấn thương yo-yo 'đã tốn tiền rồi tăng lại' — **thuộc đúng hook_direction của brief**"* and leads on *"tháo rào tiếc tiền"* — that is `IidTmN02yEczfamc`'s hook, not the stamped brief's. So the residual defect is **angle choice at invocation time**, which requirement A cannot prevent.
